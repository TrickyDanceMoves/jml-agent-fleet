## Required Smoke Tests

Run these from the repository root after tenant binding has generated local config files.

```powershell
.\shared\Verify-AuditLog.ps1
```

Expected result: the hash chain validates with no broken entries.

```powershell
.\provisioner\Test-AgentPermissions.ps1
```

Expected result: every agent has only the expected Graph app permissions and directory role assignments.

```powershell
.\auditor\Invoke-ProvisioningRecommendation.ps1 -Department "Engineering" -JobTitle "Software Engineer"
```

Expected result: JSON output with `peerCount`, `confidence`, `recommendedLicenses`, and `recommendedGroups`. A department with no peers should return an empty recommendation set and an explanatory message.

```powershell
.\auditor\Invoke-RiskScore.ps1 -Operation joiner -UserPrincipalName NEW_USER -Licenses "INTUNE_D" -Groups "All-Staff"
```

Expected result: JSON output with `riskLevel`, `score`, `blocked`, `dualApproval`, and `reasons`.

```powershell
cd .\api
npm install
node -e "const { validateEvent } = require('./src/lib/event-validator'); for (const f of ['hire','transfer','terminate']) { const e = require('./test-fixtures/' + f + '.json'); console.log(f, validateEvent(e)); } const bad = require('./test-fixtures/malformed-missing-ticket.json'); console.log('malformed', validateEvent(bad));"
```

Expected result: `hire`, `transfer`, and `terminate` are valid; `malformed` is rejected because termination events require `ticketRef`.

```powershell
cd ..\worker
npm install
node -e "const dispatcher = require('./src/agent-dispatcher'); console.log(Object.keys(dispatcher));"
```

Expected result: dispatcher module loads without dependency or syntax errors.

```powershell

npm install
npm start
```

Expected result: console launches, operator selector appears, each tab renders, and no preload/main-process errors appear in the terminal.

## Production Readiness Recommendations

1. Keep README claims tied to implemented behavior. If a feature is not callable from the repo or packaged app, label it roadmap.
2. Preserve a clean tenant setup path: provisioner scripts should remain the source of truth for app registrations, certificates, consent links, config generation, and permission repair.
3. Add lightweight Node tests for `api/src/lib/event-validator.js`, `api/src/adapters/bamboohr.js`, and `worker/src/agent-dispatcher.js`.
4. Add PowerShell parse tests for every `*.ps1` script using the Windows PowerShell 5.1 parser, because the documented runtime is 5.1.
5. Add a no-secrets release check that fails if `config.json`, `local.settings.json`, `worker.config.json`, audit logs, report outputs, or operator auth files are staged.
6. For demos, seed a non-production tenant with synthetic users, synthetic groups, synthetic licenses, and sanitized audit events only.
7. Keep Workload Identity CA as an accepted/licensed control, not a missing engineering task.
8. Enterprise Agents Microsoft IQ requirement is met — Foundry IQ grounds risk/approval decisions on the JML policy corpus and is visible in the demo (`electron-app/lib/foundry-iq.js`).

## Final Demo Script

1. Show the architecture diagram and explain the control plane: HR event to queue/API, queue to agents, agents to Graph, every action to hash-chained audit.
2. Run a joiner in WhatIf mode, show recommendation and risk output, then submit through the console.
3. Run a leaver flow through soft stage, show dual-approval gate for hard stage, then show audit evidence.
4. Run UEBA/drift/risky-user scan from the Security tab.
5. Show Sentinel/Blob export controls and the audit-chain verifier.
6. Close with accepted gaps: Workload Identity CA license dependency and additional HRIS adapters on roadmap.
